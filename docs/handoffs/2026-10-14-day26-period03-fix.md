# 26일차 3교시 검토·복구 · 2026-10-14

요청은 사용자가 마친3교시에서 빠진 부분과 오류를 확인하고 현재 구조 안에서 수정하는 것이다. Desktop의 `26일차 · 같은 입력의 Lake·Mongo와 광고 보고서.html`을 기준으로 확인했다. 앞선 검증 기록에 저장한 교안 SHA와 현재 첨부 파일 SHA가 같다. 새 서버·examples·별도 검증 폴더는 만들지 않았다.

## 완료 결과와 원인

- `ads/lake_files.py`의 완료 파일 이름 `summary.json`을 `manifest.json`으로 수정했다. 문제 틀의 예시 이름을 실제 정답 이름 대신 사용한 상태였다. 사용자가 작성한 계산 함수·writer·로컬 변수명 `pthh`는 그대로다.
- `ads/management/commands/compare_player_lake_versions.py`는 시작 시0 bytes였다. 교안의 전체 코드를 그 파일에 적용했다. `build_player_lake.py`는 이미 교안과 같아 수정하지 않았다.
- `compare_player_snapshots.py`에는 Lake 비교 코드와 Command가 중복으로 들어가 기존24일차 `--output` 기능이 사라져 있었다. 시작 소스를 검증 기록에 보존한 뒤 직전 커밋의 기존 snapshot 비교 구현으로 복구했다. 파일 전체를 다른 설계로 재작성하지 않았다.
- 기존 `run-001/002`에는 history/current/summary만 있었다. 교안의 불완전 run 복구 지침에 따라 보존하고 새 `run-003/004`에 각각 history/current/manifest를 생성했다. 이전 파일을 삭제하거나 이름을 바꾸지 않았다.

실제 선택 입력은 `data/handoff/day25-run1/player-context-changes.ndjson`이다. 입력 SHA는 `18dbb0bd715f69a4bfde646623cd3d39932f9c147fdf7858f6276732bb51e154`, N=H=K=56이다. 교안의107행 출력은 예시이므로 현재56행을 늘리거나 다른 파일로 바꾸지 않았다. 두 새 run의 source/history/current_matches는 모두true다. 저장 파일 SHA는 history=`ad682d307f0508b2cbffbd48beece93ad974cb03e7cc9161b3b725d64e4d3a98`, current=`2814cd044e44ebe3f92e63c3e53631aa04a41a87c34cae0b948829c458df60ac`다.

## 작업 시작 전 Git 상태

Chapter3 상위 작업 폴더: **Git 상태 확인 불가: 저장소 아님**. 광고 저장소는 `C:\MLO01-01\Chapter3\ad_server`이며 HEAD는 `d68b511 day25 - 챕터2`다. staged 변경은 없었다.

작업 시작 전에 존재한 unstaged 변경은 `ads/lake_files.py`, `ads/management/commands/compare_player_snapshots.py`다. untracked 파일은 `ads/management/commands/build_player_lake.py`, `ads/management/commands/compare_player_lake_versions.py`다. 모두 사용자 변경으로 취급해 내용을 읽고 짝 문서를 먼저 맞췄다. 원래 소스·SHA·Git 상태는 [검증 기록](../server-routing/verification/day26-period03.json)의 `source_before`, `git_start`에 있다.

Git stage/reset/commit은 수행하지 않았다. 종료 시 snapshot 소스는 HEAD와 같아 Git 변경 목록에서 사라졌지만 이는 이번 복구 작업이며 시작 변경이 없었다는 뜻이 아니다. build 명령은 시작 SHA 그대로 유지했다. lake의 Git diff에는 사용자의3교시 함수 추가와 이번 한 줄 수정이 함께 있으므로 전체 diff를 에이전트 작업으로 주장하지 않는다.

## 이번 작업 파일

개발 수정은 기존 `ads/lake_files.py`, `ads/management/commands/compare_player_snapshots.py`, 비어 있던 `ads/management/commands/compare_player_lake_versions.py`, 기존 `ads/test_events.py`다. 초급 예제는 앞 교시 배치에 맞춰 `tools/basics/day26_period03.py`에 추가했다. 별도 테스트 파일은 만들지 않고 기존 `PlayerLakeTests`에6개 검사를 추가했다.

실제 결과물은 `data/lake/gold/player_current/run-003`과 `run-004` 각각의 `history.ndjson`, `current.ndjson`, `manifest.json` 총6개다. 수정·이동·삭제한 기존 데이터는 없다. 변경한 라우팅 문서는 lake/snapshot/test_events 짝 문서와 `current-progress-index.md`이고, 두 관리 명령·초급 예제·새 결과6개의 짝 문서를 추가했다. build 명령 소스는 보존하면서 기존에 없던 문서만 등록했다.

## 설계·책임 경계

계산과 새 run 저장은 `ads/lake_files.py`, CLI 연결은 build 명령, 실제 결과 파일의 SHA·행 수 검증과 비교는 Lake 비교 명령이 맡는다. snapshot 파일 비교는 기존 snapshot 명령이 맡는다. 광고의 공개 변환을 재사용하며 게임 ORM을 불러오지 않는다. 기존 `ads/exporting.py`의 writer는 변경하지 않았다.

동결 입력·단일 작성자·manifest 마지막 저장이라는 교안 계약을 유지한다. 저장 실패로 manifest 없는 폴더가 남으면 소비하지 않고 새 이름을 선택한다. 기존 run 재사용 거절은 의도한 동작이다. MongoDB 연결·업무 문서·프로세스·VS Code 터미널은 조작하지 않았다.

## 검증과 문서 정합화

아래 명령은 광고 작업 폴더에서 실행했다.

```powershell
python ad_config/manage.py test ads.test_events.PlayerLakeTests ads.test_events.ContextHandoffTests ads.test_events.ContextApiTests ads.test_events.EventAuthTests ads.tests.AuthenticationTests --verbosity 1
python ad_config/manage.py check
python tools/basics/day26_period03.py
```

결과는39개 통과, Django 오류0, 초급 출력64/True다. 테스트는 격리된 임시 입력·run과 mock DB를 사용했다. Windows sandbox 임시 폴더 권한 문제를 피하기 위해 테스트 명령만 실제 사용자 실행 환경에서 검증했다. 실제 Mongo 데이터에 쓰지 않았다.

실제 관리 명령으로 인계의 history 확인 → 새 run-003 저장 → 같은 경로 재작성 거절 → 새 run-004 저장 → 두 run 비교 → 인계 current 재확인을 수행했다. 파일 SHA를 통해 기존 입력·인계·checkpoint·사용자 run 총14개 보존을 확인했다. 첫 current는 village-game:1/version461/deleted=false/coins26으로2교시 결과와 같다. 입력 SHA·미리보기 목록 SHA·저장 파일 SHA를 구별했다.

writer와 두 관리 명령은 교안 완성 코드 AST와 같고 build_lake_version은 기존 로컬명 pthh를 path로 치환해 비교하면 AST가 같다. 이전 계산 함수4개와 build 명령은 시작 상태와 동일하다. 검증 뒤 별도 문서 정합화 단계에서 Python6개와 결과물6개의 짝 문서·색인·시그니처·책임·직접 호출을 확인했다.

`routing-doc-auditor` CLI는 기존 `docs/server-routing/README.md`가 없어 exit1로 실행을 완료하지 못했다. 새로운 README를 임의 생성하지 않고 같은 검사기의 AST API와 실제 `current-progress-index.md`를 대조해 누락0을 확인했다. CLI 성공으로 기록하지 않는다. `git diff --check`는 통과했고 LF/CRLF 변환 안내만 있었다.

## 제한과 다음 실행

실제 Mongo 연동 테스트와 GUI 광고 화면은3교시의 파일 저장 범위에 포함되지 않아 실행하지 않았다. 기존 `**/data/` ignore 규칙 때문에 생성 데이터와 그 경로를 따른 짝 문서는 Git에서 무시된다. 로컬 파일·색인은 존재하며 ignore 정책·강제 stage는 변경하지 않았다. 별도의 모듈 재구성이나4교시 개발은 하지 않았다.

.\.venv\Scripts\Activate.ps1
